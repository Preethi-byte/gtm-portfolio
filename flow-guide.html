Exact Flow formula resources

Create each resource in Manager → New Resource → Formula. Use the API names below. The custom engagement date is maintained by the user in this version.

fOverdue · Boolean
AND(NOT({!$Record.IsClosed}), {!$Record.CloseDate} < {!$Flow.CurrentDate})
fMissingValue · Boolean
AND(NOT({!$Record.IsClosed}), OR(ISBLANK({!$Record.Amount}), {!$Record.Amount} = 0))
fActivityReview · Boolean
AND(NOT({!$Record.IsClosed}), OR(ISBLANK({!$Record.Last_Engagement_Date__c}), {!$Record.Last_Engagement_Date__c} <= ({!$Flow.CurrentDate} - 21)))
fReviewRequired · Boolean
OR({!fOverdue}, {!fMissingValue}, {!fActivityReview})
fReviewReasons · Text
IF({!fOverdue}, "Overdue close date; ", "") & IF({!fMissingValue}, "Missing or zero amount; ", "") & IF({!fActivityReview}, "Missing or stale engagement date; ", "")
fStateChanged · Boolean
OR({!$Record.Review_Required__c} <> {!fReviewRequired}, BLANKVALUE({!$Record.Review_Reasons__c}, "") <> {!fReviewReasons})

The missing/zero rule deliberately does not flag negative amounts. The activity rule includes exactly 21 days and does not flag future dates. Agree those policies before activation.

Owner playbook · Verify before changing commercial data

Overdue close date

Review the latest buyer conversation. Confirm whether the deal remains active and when the buyer expects a decision.

Action: update the close date only when supported by buyer evidence and your team’s process.

Missing or zero amount

Confirm scope, pricing, and whether zero is a legitimate exception.

Action: enter the confirmed value or document the unresolved question with the owner.

Missing or stale engagement

Check for unrecorded contact before assuming inactivity.

Action: enter the verified date in Last Engagement Date and log the interaction or next step.

What happens after the owner acts?

The next daily run recalculates the review fields. A healthy opportunity drops out of the report. An unresolved issue remains flagged. This version has no acknowledge, snooze, email alert, or automatic task creation.

For same-day clearing, run the Flow debug in a sandbox for verification, or implement a separate, tested refresh mechanism. The daily version does not promise immediate updates.

Expose engagement date for relevant users; make review fields read-only to ordinary users. Confirm field visibility, opportunity sharing, and report access.

Configure, then test.

  1. Create the schedule-triggered Flow, its six formula resources, Decision, and Update Records as shown in Flow design.
  2. Save the Flow as a draft. Add sample records and debug with rollback enabled where available. Compare computed values with expected outcomes.
  3. Add a before-save record-triggered Flow on Opportunity updates: entry IsClosed = True AND Review_Required__c = True. Use Assignment to set Review_Required__c to False and Review_Reasons__c to an empty string. This clears stored flags on closed deals.
  4. Use Update Records fault handling for failures: connect a fault path to an approved admin alert or error log. Verify the chosen handler in your org.
  5. Create the report with the filters and columns in Review report. Confirm owners can open only records they are permitted to access.
  6. After sandbox checks pass, activate and verify one scheduled run. Review org execution limits and existing Opportunity automation before widening the scope.
