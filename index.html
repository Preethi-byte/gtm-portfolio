Expand prospect intelligence without losing CRM control.

Business problem
Enrichment introduced a governance question alongside a coverage opportunity: how should external provider data enter Salesforce without replacing trusted values or creating conflicting records?
What I delivered
I translated prospecting requirements into Clay write-back, matching, deduplication, and consent guardrails, retaining Salesforce as the system of record and limiting enrichment writes to designated Clay fields. I also reviewed Sales Navigator adoption, validated ZoomInfo records, implemented and supported Weflow and Kernel, and coordinated Gainsight–Salesforce sync requirements.

Run the batch to inspect a decision.
Execution order: which rule runs first?
  1. Normalize email case and surrounding whitespace.
  2. Collect suppressed addresses across the whole batch. Block every matching row, including earlier rows.
  3. Hold missing emails or verification statuses other than valid.
  4. Hold records missing LinkedIn, firmographics, or ownership.
  5. Check whether an eligible row already reserved the normalized email. If so, mark duplicate.
  6. Reserve the eligible address and prepare a template draft for human review.

These rules execute in JavaScript. In a Salesforce Flow design, the same stages would use record queries, loops, Decisions, and Assignments. The reservation is currently batch-local; cross-run duplicate prevention would need stored state.

How a prospect becomes draft-ready

Each sample supplies simulated email verification, suppression, ownership, and field-completeness inputs. The code applies shared rules before reserving a contact for one eligible segment. Records that fail a check receive a reason. Ready records get a reviewable template draft. The browser runs the logic on sample data without external connections or email delivery.

POINT OF VIEW

Automate the work. Own the decision.

I would use an LLM to summarize meetings, draft follow-ups, or extract evidence for account research. I would keep consent, suppression, deduplication and field-level write permissions in explicit rules. Forecast changes and decisions to send outreach would go to an accountable owner.

For agent evaluation, I would test against examples with missing evidence, conflicting owners, duplicate contacts, and suppressed addresses. For a GTM stack audit, I would compare vendor spend with adoption, data quality and workflow performance before recommending a replacement.
